# Контракт сервиса заказов

Все тела запросов и ответов — JSON. Заказ сохраняется в базе данных.
Поля карточки: `id` (целое), `account_id` (целое), `item` (строка),
`quantity` (целое), `created_at` (дата и время ISO 8601).

## POST /orders

Обязательные поля: `account_id >= 1`, `item` длиной 1–200 символов,
`quantity >= 1`. Пример:

```json
{"account_id": 1, "item": "Кофемолка", "quantity": 2}
```

Перед записью сервис запрашивает `GET /accounts/{account_id}` по адресу
`ACCOUNTS_URL`. Ответ 201 содержит карточку с присвоенным `id` и `created_at`.
Ошибки: 422 — неправильное или отсутствующее поле (`detail[].loc` указывает
поле); 404 — клиент не найден; 503 — сервис клиентов недоступен, вернул
неожиданный статус или некорректную карточку. При 404/503 заказ не записывается.
`ACCOUNTS_TIMEOUT_SECONDS` по умолчанию 2 секунды, допустимо больше 0 и до 2,5.

## GET /orders/{id}

`id` — целое число. Ответ 200 — карточка заказа.
404 — `{"detail": "Заказ 999 не найден"}` с запрошенным номером.
422 — номер невозможно преобразовать в целое.

## GET /orders?account_id=1&limit=50&offset=0

Обязательный `account_id >= 1`. `limit`: 1–200, по умолчанию 50.
`offset >= 0`, по умолчанию 0. Ответ 200 — массив карточек только указанного
клиента по возрастанию id; без заказов — `[]`. 422 — неверные параметры.
Чтение заказов не требует доступности сервиса клиентов.

## GET /health

200: `{"status":"ok","service":"orders"}` — процесс отвечает.
Это проверка процесса, а не доступности соседнего сервиса.
