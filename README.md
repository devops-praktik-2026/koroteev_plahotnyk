# Практикум по DevOps

Учебный проект. Здесь лежат два сервиса: один готов и служит
образцом, второй вы дописываете сами. За курс вы доведёте систему от запуска
на своём ноутбуке до установки версии на сервер, который сами же опишете
кодом.

---

##  (занятие 1)

1. **Создайте свой репозиторий.** Нажмите «Use this template» → «Create a new
   repository». Не форк: вам нужна своя чистая история и свой список задач.

2. **Позовите напарника.** Settings → Collaborators → добавьте второго участника
   с правом записи.

3. **Заведите доску.** Вкладка Projects → New project → Board. Колонки:
   `Список задач` · `Готово к работе` · `В работе` · `На проверке` · `Готово`.
   Правила — в [docs/board.md](docs/board.md).

4. **Проверьте, что на компьютере всё есть, и соберите окружение:**

   ```bash
   make check
   make setup
   make test
   ```

   Первая команда скажет, чего не хватает; полный разбор — в разделе
   [«Что должно быть на компьютере»](#что-должно-быть-на-компьютере).
   После `make test` должно быть зелено. 

5. **Посмотрите на образец.** Запустите сервис клиентов:

   ```bash
   make run
   ```

   Команда сначала приведёт структуру базы данных к нужному виду, потом
   запустит сервис. Откройте <http://localhost:8001/docs> — это не рукописная
   документация, она собрана из кода сама. Нажмите «Try it out» у запроса
   создания клиента и создайте кого-нибудь прямо из браузера.

6. **Сломайте тест нарочно.** Откройте
   `services/accounts/tests/test_accounts_api.py`, поменяйте в любом тесте
   ожидаемый код ответа на неправильный, запустите `make test` и прочитайте,
   что пишет pytest. Верните обратно.

7. **Разложите задачи по доске.** Готовые формулировки — в
   [docs/backlog.md](docs/backlog.md). Возьмите задачи этапа 1 в колонку
   «Готово к работе», остальные оставьте в списке.

8. **Запишите свои критерии готовности** в
   [docs/definition-of-done.md](docs/definition-of-done.md) — это ваша
   договорённость о том, когда задачу разрешено считать сделанной.

## Что здесь лежит

```
services/accounts/   сервис клиентов — ГОТОВ, это образец
services/orders/     сервис заказов — ЗАГОТОВКА, дописываете вы
infra/server-image/  образ учебного «сервера»: ssh и надзиратель
infra/terraform/     описание стенда кодом 
infra/ansible/       сценарий настройки серверов 
docs/                задачи, правила доски
.github/workflows/   автоматические проверки
compose.yaml         запуск всей системы одной командой
Makefile             короткие команды: make help
```

## Команды

Одинаковые на всех системах, включая Windows.

```
make help      список всех команд
make setup     создать окружение и поставить зависимости
make test      прогнать все тесты
make cov       тесты с показом покрытия построчно
make lint      проверить стиль кода
make fmt       привести код к единому виду
make run       запустить сервис клиентов на своей машине
make migrate   применить миграции базы данных
make up        поднять всю систему в контейнерах
make down      остановить и удалить данные
```

## Что должно быть на компьютере

Не гадайте — запустите проверку. Она ничего не ставит и не меняет, только
смотрит и рассказывает:

```bash
make check
```

А если `make` ещё не стоит — то же самое напрямую:

```bash
python3 scripts/check_env.py     # Linux, macOS, WSL
python scripts\check_env.py      # Windows
```

Она назовёт всё, чего не хватает, и что с этим делать. Ниже подробности.

### Нужно с самого начала

| Что | Зачем | Как проверить |
| --- | --- | --- |
| **Python 3.11 или новее** | на нём написаны оба сервиса | `python3 --version` |
| **Модуль venv** | отдельное окружение проекта | `python3 -m venv --help` |
| **Git** | вся работа с кодом | `git --version` |
| **make** | короткие команды проекта | `make --version` |

`make` ставится на все системы, включая Windows, — команды у всех получаются
одинаковые. Где его взять на Windows, написано ниже.

Плюс **5–10 ГБ свободного места** на диске: образы и данные занимают заметно.

### Понадобится позже

| Что | Зачем | Как проверить |
| --- | --- | --- |
| **Docker** | запуск сервисов в контейнерах | `docker --version` |
| **docker compose** | запуск всей системы одной командой | `docker compose version` |




#### Про каждую из трёх программ

**Python.** Если ставите вручную с [python.org](https://www.python.org/downloads/),
на первом экране установщика обязательно отметьте **Add python.exe to PATH**.
Это самая частая причина того, что дальше ничего не работает. Признак беды —
сообщение «py не является внутренней или внешней командой»: переустановите
с этой галочкой.

**Git.** Ставится с [git-scm.com](https://git-scm.com/download/win), если
winget недоступен. Все настройки установщика можно оставить по умолчанию.

**make.** Пакет `ezwinports.make` — это GNU Make 4.4.1, современная версия.
Не берите `GnuWin32.Make`: там версия 3.81 от 2006 года, и она спотыкается
на путях с пробелами. Другие способы, если winget нет:

```powershell
choco install make        # если стоит Chocolatey
scoop install main/make   # если стоит Scoop
```

Можно и вручную: [архив ezwinports](https://sourceforge.net/projects/ezwinports/files/),
файл вида `make-4.4.1-without-guile-w32-bin.zip` — распаковать, а папку `bin`
добавить в переменную среды PATH.

#### Если winget не находит пакеты

Обновите список источников (`winget source update`) или поставьте «Установщик
приложений» из Microsoft Store — winget входит в его состав.

#### Терминал

Подойдёт любой: Windows Terminal, встроенный PowerShell, терминал внутри
VS Code. `cmd` тоже работает, но примеры в курсе рассчитаны на PowerShell.


### macOS

```bash
xcode-select --install        # даёт git и make
brew install python@3.12
```

Docker: `brew install --cask docker`, либо Rancher Desktop, либо OrbStack —
любой из них даёт и `docker`, и `docker compose`.

### Linux (Ubuntu, Debian)

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git make
```

Docker ставится по официальной инструкции с docker.com. После установки
обязательно:

```bash
sudo usermod -aG docker $USER
```

и перезайдите в систему — иначе каждая команда docker будет требовать `sudo`,
а половина примеров в курсе перестанет работать как написано.

### Что скрывается за короткими командами

`make` — это просто список сокращений, записанный в файле `Makefile`.
Загляните в него, там всё видно. Вот основное:

| Команда | Что выполняется |
| --- | --- |
| `make check` | `python3 scripts/check_env.py` |
| `make setup` | `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -e "./services/accounts[dev]" -e "./services/orders[dev]"` |
| `make test` | `.venv/bin/pytest` |
| `make cov` | `.venv/bin/pytest --cov-report=term-missing` |
| `make lint` | `.venv/bin/ruff check .` и `.venv/bin/ruff format --check .` |
| `make fmt` | `.venv/bin/ruff format .` и `.venv/bin/ruff check --fix .` |
| `make migrate` | `cd services/accounts`, затем `../../.venv/bin/alembic upgrade head` |
| `make run` | миграции, затем `uvicorn accounts.main:app --reload --port 8001` |
| `make up` | `docker compose up --build -d` |
| `make down` | `docker compose down -v` |

Пути здесь показаны для Linux и macOS. На Windows окружение устроено иначе —
вместо `.venv/bin/` подставляется `.venv\Scripts\`, вместо `python3` — `py`.
Makefile делает это сам, вручную ничего менять не нужно.

### Если образы не скачиваются

Доступ к официальному хранилищу образов Docker из России ограничен, и
`docker pull` падает с отказом. Лечится зеркалом.

**Docker Desktop:** Settings → Docker Engine, добавить в JSON и нажать
Apply & restart:

```json
{
  "registry-mirrors": ["https://mirror.gcr.io"]
}
```

**Linux:** то же самое в файл `/etc/docker/daemon.json`, затем
`sudo systemctl restart docker`.

Проверить, что помогло:

```bash
python3 scripts/check_env.py --docker
```

Зеркала — сторонние сервисы: они отстают от оригинала и иногда пропадают.
Проверьте своё заранее, а не в тот момент, когда нужно собрать образ.


Три правила, которые действуют весь курс:

1. **Нет карточки — нет кода.** Любое изменение начинается с задачи на доске.
2. **Свои изменения в основную ветку вносит не автор,** а напарник.
3. **В запросе на внесение обязательно `Closes #номер`.** Тогда карточка
   переезжает в «Готово» сама и доска не врёт.

## Два сервиса

```
Клиент  →  Сервис заказов  →(по сети)→  Сервис клиентов  →  PostgreSQL
              вы пишете                    дан готовым
```

**Сервис клиентов** хранит карточки клиентов: создать, прочитать, изменить,
удалить, показать список. К нему написаны тесты, настроены проверки и миграции
базы данных. Смотрите на него как на учебник — то же самое вам предстоит
сделать своими руками.

**Сервис заказов** пока умеет только отвечать на вопрос «жив ли ты». За курс
в нём появятся три запроса: создать заказ, получить заказ, получить список
заказов клиента. Перед созданием заказа сервис должен сходить по сети в сервис
клиентов и убедиться, что такой клиент есть.

Самое интересное начинается там, где эти двое разговаривают друг с другом:
что делать, если сосед не отвечает, как выкатывать их по отдельности, как не
сломать один, меняя другой.
