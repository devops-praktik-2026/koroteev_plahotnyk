# 1.7 Защита основной ветки

Дата проверки: 29 октября 2026 года.

Активный набор правил «Защита main» применяется к основной ветке.
Обход правил не разрешён ни одному участнику.

## Настройки

- Изменения вносятся только через pull request.
- Требуется минимум одно одобрение второго участника.
- После новых коммитов старые одобрения сбрасываются.
- Ветка PR должна содержать актуальные изменения основной ветки.
- Обязательные проверки: «Стиль кода», «Тесты», «Сборка образов»,
  «Поиск паролей».
- Удаление основной ветки и force push запрещены.

«Публикация образа» не является обязательной проверкой PR: она запускается
после слияния, только при push в `main`.

## Практическая проверка

Для проверки используется отдельная ветка `main-protection`.
Проверочный PR: https://github.com/devops-praktik-2026/koroteev_plahotnyk/pull/31.

### Прямой push

Попытка `git push origin HEAD:refs/heads/main` отклонена с ошибкой GH013:
`Changes must be made through a pull request`.
GitHub также сообщил об отсутствии четырёх обязательных проверок.
SHA основной ветки до и после попытки совпал:
`f9fde6eeb4c4798d717cdd206f896662dc63780c`.

### PR с упавшей проверкой

Коммит `b156aa4` добавил временный `scripts/protection_probe.py`
с намеренной ошибкой оформления (`protection_probe=1`).
[Запуск Actions](https://github.com/devops-praktik-2026/koroteev_plahotnyk/actions/runs/40860959867)
подтвердил: «Стиль кода» — FAILURE, тесты, сборка и поиск паролей — SUCCESS.
Публикация образа ожидаемо пропущена на PR.

Попытка слияния через GitHub API с указанием точного SHA коммита
отклонена с HTTP 405 и сообщением:

```text
Required status check "Стиль кода" is failing.
```

### PR без одобрения

При той же попытке GitHub отдельно сообщил:

```text
At least 1 approving review is required by reviewers with write access.
```

Состояние PR — `BLOCKED`, решение ревью — `REVIEW_REQUIRED`.
Одобрение за второго участника не выставлялось.

### Завершение проверки

Временный файл с ошибкой удалён следующим коммитом. В итоговом изменении
остались только отчёт и свидетельства проверок в `docs/evidence/1.7/`.
После успешных автоматических проверок PR должен проверить и слить напарник.
Слияние этого PR закроет карточку #8.
